# 로컬 에이전트 (폐쇄망용)

[![CI](https://github.com/MizzleAa/Agent-Tools/actions/workflows/ci.yml/badge.svg)](https://github.com/MizzleAa/Agent-Tools/actions/workflows/ci.yml)

Qwen 모델을 내 PC 에서 돌리고, 그 위에 **직접 만든 에이전트 루프**와 **브라우저 관리 화면**을 얹은 프로젝트.
외부 서비스 없이 `llama-server.exe` + GGUF 모델 파일 + 파이썬만으로 동작하므로 폐쇄망에 그대로 옮길 수 있다.

**화면 사용법(캡처 포함)은 [docs/사용자설명서.md](docs/사용자설명서.md)** — 이 README 는 설치 · 구조 · 개발용이다.

```
브라우저 ──► web/ (React 화면) ──► /api/v1 ──► server/ (FastAPI) ──► agent/loop.py ──► llama-server (Qwen GGUF, GPU)
                                               │
                                               └─► 도구: 파일 읽기/쓰기/검색, PowerShell, Python (승인·샌드박스)
```

## 빠른 시작 (이 PC)

1. **`start.cmd` 더블클릭** → 브라우저에 `http://127.0.0.1:8765` 가 열리고 모델 서버도 같이 켜진다.
   처음 한 번은 `runtime\downloads` 의 llama.cpp zip 을 자동으로 풀고(1분 이내) 모델을 올린다(수십 초).
   오른쪽 위 표시가 **"모델 준비됨"** 이 되면 쓸 수 있다.
2. (선택) 속도·VRAM 점검: `.venv\Scripts\python scripts\check_env.py --load`
3. 터미널로 쓰려면:
   ```powershell
   .venv\Scripts\python cli.py run "workspace 폴더에 뭐가 있는지 정리해줘"
   .venv\Scripts\python cli.py run "numbers.txt 합계 계산" --profile coder --show-thinking
   ```
4. 점수로 비교: `.venv\Scripts\python eval\run_eval.py` (모델·프롬프트를 바꾼 뒤 꼭 돌려볼 것)

## 폐쇄망으로 옮기기

| 어디서 | 무엇을 |
|---|---|
| 인터넷 PC | `powershell -ExecutionPolicy Bypass -File scripts\make_offline_bundle.ps1` → `dist\agent-offline\` 생성 (약 6GB: 프로젝트, 모델, llama.cpp, 파이썬 wheel, Python·VC++ 설치 파일, SHA256SUMS) |
| 반입 | `dist\agent-offline\` 폴더를 통째로 복사 |
| 폐쇄망 PC | (Python 3.12 없으면 `installers\python-*.exe` 설치) → `powershell -ExecutionPolicy Bypass -File agent\scripts\install_offline.ps1` → `start.cmd` |

폐쇄망 PC 조건: Windows 10/11 x64, NVIDIA 드라이버 R580 이상 (CUDA 13 빌드), 8B 모델 기준 VRAM 약 7GB.

사용자 프로젝트용 개발 도구: 번들에 규격 V1·V2 판정 도구(python: `pyflakes`·`pytest`, node: `eslint`·`@eslint/js`·`globals`)가
`agent\packages\` 로 들어간다 (`scripts\fetch_dev_tools.ps1`, 따로 돌려도 된다). 폐쇄망 설치가 `packages\.offline` 을 만들면
에이전트가 실행하는 `pip`·`npm` 이 인터넷 색인 대신 이 폴더만 본다 (`PIP_FIND_LINKS`·`PIP_NO_INDEX`·`npm_config_cache`·`npm_config_offline`).
그래서 프로젝트 `.venv` 에 `pip install pyflakes`, 프로젝트에 `npm install -D eslint` 가 인터넷 없이 된다.

## 화면과 API

- **API** (`/api/v1`, FastAPI): 자원별 라우터 — `runs`(실행·SSE·승인·중지), `profiles`·`workflows`(입력창 목록),
  `status`·`runtime`·`models/active`(모델 서버), `intranet`·`apis`·`hosts`·`secrets`(사내 연결), `workspace/folders`(작업 폴더·파일 보기, 읽기 전용),
  `locations`(공유 위치 허용 목록 · 계정 · 파일 탐색기, 읽기 전용),
  `settings/*`(설정 화면), `auth/*`(로그인 · 비밀번호 · 비밀번호 찾기), `me/*`(내 사내 API 계정),
  `admin/*`(사용자·회사 · 외부 AI 모델 · 기록·사용량 · 접속 설정).
  요청·응답은 모두 pydantic 모양으로 정해져 있고, 오류는 항상 `{"detail": "설명"}` 하나다 (입력 검증 오류도 400).
  상태를 바꾸는 요청은 `X-Agent-Token` 헤더가 필요하다 (화면은 index.html 에 들어 있는 토큰을 쓴다).
  계약: `http://127.0.0.1:8765/api/v1/openapi.json` · 사람이 보는 문서: `/api/docs` (Swagger UI, 인터넷이 되는 PC 에서).
- **화면** (`web/`, React 19 + TypeScript + Vite): 기능별 폴더 — `features/chat`(대화·도구·승인·워크플로 노드),
  `features/files`(작업 폴더·코드 보기 · 파일 탐색기), `features/status`(상태·연결), `features/settings`(용도·워크플로·모델·프롬프트…), `features/sidebar`,
  `features/auth`(로그인 · 비밀번호), `features/account`(내 계정), `features/admin`(관리).
  API 타입은 `web/openapi.json` 에서 생성한다(`src/api/schema.d.ts`). 서버와 화면의 모양이 어긋나면 `tsc` 와
  `tests/test_api_contract.py` 가 알려 준다.
- **빌드 결과**(`web/dist`)를 관리 서버가 그대로 내보낸다. `start.cmd` 는 소스가 바뀌었으면(npm 이 있는 PC 에서) 자동으로 다시 빌드한다.
  폐쇄망 PC 에는 빌드 결과만 옮기므로 Node·npm 이 필요 없다.

API 나 화면을 고칠 때:
```powershell
# API 를 바꿨으면: 계약 저장 → TS 타입 다시 만들기 (안 하면 tests/test_api_contract.py 가 실패)
.venv\Scripts\python scripts\export_openapi.py
cd web; npm run gen:api
# 화면 개발: 관리 서버를 고정 토큰으로 켜고 Vite 개발 서버(바꾸면 바로 반영)를 쓴다
$env:AGENT_TOKEN = 'dev'; .venv\Scripts\python -m server        # 창 1
cd web; $env:AGENT_TOKEN = 'dev'; npm run dev                       # 창 2 → http://127.0.0.1:5173
# 점검
cd web; npm run typecheck; npm test; npm run build
.venv\Scripts\python -m pytest -q
```

## 실행 화면에서 고르는 것

- **승인**: 매번 묻기 / 파일 쓰기는 자동 / 전부 자동(명령 실행·API 변경 포함). 승인 칸의 **"이번 실행은 전부 승인"** 으로 도중에 바꿀 수도 있다.
- **최대 스텝**: 20 / 50 / 100 / 무제한 (무제한이면 시간 제한도 없음 — 중지 버튼으로 멈춤).
- **이어서 하기**: 최종 답변 아래 칸에 추가 지시나 힌트를 쓰면 이전 대화를 그대로 이어받아 계속한다. 한도·반복으로 멈춘 작업도 여기서 이어간다.
- **반복 감지**: 같은 수정을 두 번 하면 경고, 세 번째면 멈추고 "어디서 막혔는지" 정리한다. 그때 힌트를 주고 이어서 하면 된다.
- 오래 돌아서 대화가 길어지면 오래된 도구 결과부터 자동으로 줄여 모델 컨텍스트(16k)를 넘지 않게 한다.
- **대화마다 작업 폴더**: `workspace\2026-11-05_1430_요청 첫 문장\` 이 생기고, 에이전트가 만드는 파일·명령 실행은 그 안에서 한다.
  이름은 요청의 첫 문장까지, 문장 부호 없이, 단어 중간에서 자르지 않는다 (모델이 경로를 옮겨 적다 틀리지 않게).
  같은 대화를 이어 가면 같은 폴더. 폴더 안 `작업기록.md`(요청 → 한 일 → 답변 → 폴더 안 파일)와
  `workspace\작업목록.md`(전체 목록)는 실행이 끝날 때마다 자동으로 정리된다. 답변 아래 📁 버튼으로 폴더를 연다.
  (끄려면 `settings.yaml` 의 `session_folders: false`)
- **작업 폴더 경계** (`agent/boundary.py`): 파일 도구는 대화 폴더 밖(같은 workspace 안)에 쓰지 않는다 — 요청에 그 폴더 이름을
  적은 경우만 예외. 명령이 workspace 에 없는 폴더를 절대 경로로 가리키면(옆 폴더를 새로 만드는 길) 실행하지 않고, 명령 뒤 workspace 에
  새 폴더가 생기면 모델에게 알린다. 다른 폴더를 읽거나 거기서 옮겨 오는 것은 된다.
- **작업 폴더 · 코드** (사이드바, 답변 아래 '코드 보기'): 작업 폴더 목록(작업기록 제목) → 파일 트리 → 코드 보기(줄 번호·색 구분·복사,
  .md 는 보기 좋게/원문). 읽기 전용이고 `workspace` 바로 아래 폴더 안만 연다. `.venv`·`node_modules`·`bin`·`obj` 는 펼치지 않는다.
- 이 저장소에는 `pyproject.toml`·`pytest.ini` 를 두지 않는다 (pytest 설정은 루트 `conftest.py`). 두면 `workspace\` 안에서 만든
  사용자 프로젝트가 이 저장소를 pytest 기준 폴더(rootdir)로 잡아 설정을 물려받는다.

## 개발 규격 (`coder` 프로필)

QA 와 같은 기준으로 개발하게 한다. 원본은 `Agent_QA\기준\`(QA 소유), 에이전트가 쓰는 것은 복사본 `config\standards\`.
- **공통 규격 요약**(프롬프트 블록 `dev_standard`, 설정 › 공통 블록)은 coder 시스템 프롬프트에 항상 들어간다: 작업 순서, 프로젝트 폴더 하나 + `_scratch\`,
  프로젝트 로컬 설치·폐쇄망, 검증 등급 V0~V4, 완료 정의, 개발 보고 형식.
- **언어별 규격**(python · dotnet · node-web)은 그 언어로 파일을 쓰거나 명령을 돌리기 시작하면 그 언어 것 하나만 자동으로 붙는다
  (16k 컨텍스트 절약). `read_standard` 도구로 직접 읽을 수도 있다.
- **끝날 때 점검**: 개발 작업이면 산출물 폴더(프로젝트 폴더·README·의존성 선언·자동 테스트·.sln/테스트 프로젝트·package.json·정리 상태)와
  최종 보고(결과 줄, 요구사항별 검증표, V3 미만인데 '완료'라고 했는지)를 규격으로 점검해, 걸리면 최대 2번 되돌려 보낸다.
  보고가 '부분 완료'면 실행 상태도 `partial`(부분 완료)로 남는다.
- **실행 기록 대조** (`agent/evidence.py`, 모든 용도 — 쓰기·실행 도구가 있는 경우): 최종 보고를 이번 실행의 도구 기록·작업 폴더와 맞춰 본다.
  - 도구를 한 번도 안 썼는데 파일·실행·검증을 보고하면 한 번 되돌려 보내고, 또 그러면 `no_action` (워크플로 노드도 같음).
  - V2·V3 행: 근거로 적은 명령·테스트가 이번에 종료 코드 0 으로 실행됐는지, 그 테스트·코드가 프로젝트 자신의 코드를 거치는지
    (Python import · JS 상대 경로 import · C# ProjectReference). 아니면 되돌려 보내고, 끝까지 남으면 `done` 대신 `partial`.
  - 구현 위치 파일이 없거나, 보고·해석에 '대체·대신' 이라고 쓴 요구가 V2 이상이거나, 소스에 TODO·미구현 표시가 있으면 '완료'가 아니다.
  - 근거가 import 확인뿐이거나 Start-Process 로 띄운 것뿐이면 근거가 아니다. 근거 테스트가 '구현 위치(파일:함수)'의 함수를 부르지 않거나,
    요구 여럿을 함수 한두 개만 부르는 테스트로 V2 라 하면 걸린다. 테스트가 확장자와 다른 형식의 파일(0 바이트로 채운 .mp4 등)을 쓰면 근거가 아니다.
  - V3 인데 구현 위치의 함수가 출력(print)·값 저장뿐인 껍데기면 걸린다 (`agent/codecheck.py`: Python AST, JS·TS·C#·Java 정규식).
  - 의존성 버전(의존성·스택 줄을 실제 설치와 비교)·정리 주장(삭제 명령 기록)·한자 섞임은 답 끝 '⚠ 실행 기록 점검' 에 (참고)로만 알린다.
    스텝 한도·반복 감지로 끝난 보고에도 같은 점검을 붙인다.
- **답하지 못한 부분·넘긴 일** (모든 용도): '확인할 수 없습니다'·'알 수 없습니다'·'…되면 확인할 수 있습니다' 처럼 요청 일부를 못 했으면
  `partial`. 사용자가 '파이썬 실행 못 해' 라고 했거나 실행 도구가 없는 용도인데 '스크립트를 실행하시면' 으로 넘기면 한 번 되돌려 보낸다.
- **같은 이유의 거부**: 형식 오류·기록 압축 표시·작업 폴더 밖·같은 도구 오류로 세 번째 거부부터 방법을 바꾸라고 하고, 다섯 번째면 멈춘다.
- **끝맺지 못한 답**: 길이 한도로 잘렸거나(finish_reason=length), 도구 호출이 깨져 서버가 버렸거나, 짧은 답이 '이제 …' 문장 중간에서
  끝나면 최대 2번 이어서 하라고 되돌려 보내고, 그래도 끊기면 `partial`. 개발 작업인데 보고 형식이 아니거나 규격에 못 미친 채 끝나도 `partial`.
- **고친 오류의 재발**: 이 대화(이어서 한 이전 실행 포함)에서 '없는 이름'으로 실패한 API(ImportError·AttributeError·CS0117 …)가
  파일에 다시 들어가면 저장 결과에 바로 알린다 (`agent/known_errors.py`).
- **PowerShell 5.1**: `a && b`·`a || b`·`mkdir -p`·`rm -rf`·`ls -la`·`which`·`export` 는 같은 뜻의 5.1 문법으로 바꿔 실행하고 알린다
  (따옴표·here-string 안은 그대로). Start-Process 결과에는 '띄웠을 뿐 동작 확인이 아님'을 붙인다.
- **되돌릴 수 없는 삭제**: 작업 폴더·프로젝트 폴더를 통째로 지우는 명령(`Remove-Item -Recurse`, `rmdir /s`, `shutil.rmtree` …)은
  '전부 자동' 승인 중에도 매번 묻는다 (`__pycache__`·`_scratch` 같은 부산물 폴더와 파일 하나 삭제는 그대로).
- **설치 규칙**(`settings.yaml` 의 `policy`): 시스템 전역 설치(venv 밖 pip, `npm -g`, `dotnet tool -g`, winget 등)와
  인터넷 다운로드 명령(Invoke-WebRequest, curl, git clone 등)은 막는다. 프로젝트에 패키지를 설치하기 전에는 그 언어의
  환경 확인 명령(`pip list`, `npm ls`, `dotnet --list-sdks` 등)을 먼저 돌려야 한다.

루프 쪽 보강: 컨텍스트가 차면 오래된 도구 결과·도구 인자(파일 원문)·긴 설명 순으로 줄이고, 그래도 넘치면 오래된 턴을 지운다 ·
계획만 말하고 끝나면 실행하라고 되돌려 보내고, 끝내 실행하지 않으면 `no_action` · 시간 초과로 멈춘 명령도 그때까지의 출력과
뜻을 돌려준다 · `run_python` 과 셸 `python` 은 같은 시스템 Python · `2>&1`·CLIXML 정리와 실제 종료 코드 ·
같은 종류의 실패(시간 초과, 빌드 실패, 같은 예외)가 최근 8번 중 3번·5번이면 방법을 바꾸라고 경고.

## 설정 · 프롬프트 (용도 관리)

사이드바 **설정 · 프롬프트** 에서 코드 수정 없이 프롬프트·파라미터를 바꾼다. 저장하면 **다음 실행부터 바로** 적용된다 (재시작 불필요).

- **용도 탭**(general · coder · researcher · intranet · ＋새 용도): 역할 프롬프트, 프롬프트 구성(블록 순서),
  도구(최대 10개), 파라미터(최대 스텝·생각 모드·온도·top_p·쓰기 자동 승인·개발 규격 적용), 이 용도 전용 변수.
  **미리보기**로 조립된 시스템 프롬프트, 토큰 수(모델 서버가 켜져 있으면 정확히), 컨텍스트 예산 비율, 점검 경고를 본다.
- **공통 탭**: 모델(교체·추가·모델별 값) · 공통 블록(여러 용도가 같이 쓰는 프롬프트 조각) · 루프 메시지(되돌려 보내기·한도·반복·실패 경고 문구) ·
  도구 설명 · 변수 · 실행 파라미터(`settings.yaml` 을 주석 그대로 두고 값만) · 개발 규격 문서 · 변경 기록(보기·되돌리기) · 안내.
- 시스템 프롬프트 = **역할 프롬프트 + 고른 블록(순서대로)**. 바뀌지 않는 것을 앞에, 대화마다 바뀌는 실행 환경(폴더·날짜)을
  뒤에 두어 모델 서버가 앞부분 계산을 재사용하게 한다 (새 대화 첫 응답이 빨라짐).
- 문법: `{{변수}}`, 줄 맨 앞 `{{?run_command}}` = 그 도구를 가진 용도에만 그 줄을 넣기 (`{{?a|b}}`, `{{?!x}}`).
- 기본값은 `agent/prompt_defaults/`, 바꾼 것만 `config/prompts.yaml`·`config/agents/*.yaml` 에 저장되고, 저장 직전 내용은
  `data/settings_history/` 에 남는다. 자세한 설계와 다음에 추가할 것: `docs/프롬프트_설계.md`.

## 워크플로 (노드를 차례로)

용도 하나에 다 시키는 대신, **노드(용도 + 지시문)를 이어 붙여 정해진 순서로** 실행한다. 순서는 모델이 아니라 프로그램이 정한다
(소형 모델은 일을 스스로 나누고 합치는 걸 잘 못한다). 입력창의 용도 선택에서 `⛓ 이름`을 고르고 요청을 보내면 된다.

- 노드마다 **새 컨텍스트**로 시작하고, 앞 노드의 최종 답을 `{{노드id}}` 로 받는다 (`{{input}}` = 요청, `{{previous}}` = 같은 대화의 이전 답).
  긴 결과는 앞뒤만 넣고 전문은 대화 폴더의 `_workflow/` 에 남긴다. 노드들은 같은 대화 폴더를 쓰므로 앞 노드가 만든 파일을 읽을 수 있다.
- 모델 서버가 하나라 노드는 **하나씩** 돈다 (추가 VRAM 없음). '기다릴 노드'가 실패하면 그 노드는 건너뛰고,
  `실패하면: 멈춤`(기본)이면 워크플로가 멈춘다. 멈추면 **'멈춘 노드부터 계속'** — 끝난 노드는 다시 돌리지 않는다.
- 기본 제공: `build-review`(만들기 coder → 검토 reviewer → 고치기 coder), `research-report`(조사 researcher → 보고서 general).
  `reviewer` 는 쓰기 도구가 없는 검토 전용 용도다.
- 만들기·고치기: 설정 · 프롬프트 › **워크플로** (노드 추가·순서·기다릴 노드·지시문, 흐름도 미리 보기). 파일: `config/workflows/<이름>.yaml`.

## 사내 시스템 연결 (`intranet` 프로필)

채팅에서 **"http://wiki.intra/ 추가해줘"**, **"MES API 추가해줘, 주소는 …, 경로는 …"** 라고 하면 등록·저장(`config/connections.yaml`)·수집까지 알아서 한다
(접근 범위가 넓어지는 일이라 한 번 승인을 묻는다). 상태 탭의 **사이트 추가** 칸, **삭제** 버튼, **토큰 입력** 칸으로도 같은 일을 할 수 있다.
아래는 `settings.yaml` 에 직접 쓰는 방법이다.

**1) 검색 기능이 없는 사내 웹페이지** → 수집해서 검색 (`search_intranet`)

```yaml
intranet:
  sources:
    - name: wiki
      description: 사내 위키 (공정 매뉴얼, 장비 사용법)
      start_urls: [http://wiki.intra/]
      include_prefixes: [http://wiki.intra/]     # 이 주소로 시작하는 페이지만
      exclude_patterns: [/logout, action=edit]   # 로그아웃·편집 링크는 절대 따라가지 않게
      max_pages: 500
```

등록 후 관리 화면 **상태 탭 → "지금 수집"** (또는 `cli.py crawl`). 내용이 바뀐 페이지만 다시 색인하고, 사라진 페이지는 뺀다.
'설비', '로트' 같은 2글자 한국어 단어도 검색된다.

**2) 사내 REST API** → 등록한 API 만 호출 (`api_get` 조회는 자동, `api_send` 변경·파일 업로드는 매번 승인)

가장 쉬운 방법: 채팅에서 **"이 API 추가해줘 http://10.1.2.3:8000/docs"** 또는 상태 탭 '사내 API' 칸에 Swagger 주소를 넣는다.
`openapi.json` 을 찾아 기본 주소·엔드포인트 목록(파라미터, 업로드 필드 포함)을 자동으로 채운다.
엔드포인트가 많으면 에이전트가 `find_endpoint` 로 필요한 경로를 찾는다. 변경 요청은 상태 탭의 **'변경 요청 허용'** 을 켜야 쓸 수 있다.
내부 주소를 읽기만 하려면 "10.1.2.3 허용해줘" (또는 상태 탭 '읽기 허용된 내부 주소').
직접 쓰려면 아래처럼 `settings.yaml` 에:

```yaml
apis:
  - name: mes
    description: 생산 실행 시스템
    base_url: http://mes.intra:8080/api
    auth: {header: Authorization, secret: MES_TOKEN, prefix: "Bearer "}
    allow_methods: [GET]
    docs: |
      GET /lots/{lot_id}            로트 상세
      GET /lots?line=A1&status=RUN  라인별 진행 중 로트
```

**인증 (로그인이 필요한 API)** — 관리 화면 **'상태 · 연결' › 사내 API › 그 API 의 '인증' 칸**에서 한다.
- 문서(OpenAPI)에 인증이 정의돼 있으면 등록할 때 자동으로 채워진다: OAuth2 password 면 '계정으로 로그인' + 로그인 주소,
  bearer·apiKey 면 '토큰'. 문서의 로그인 주소가 API 서버 자신(localhost)을 가리키면 등록한 호스트로 바꿔 넣고 그렇다고 적는다 (화면에서 고칠 수 있다).
- 사용자는 그 칸에 **아이디·비밀번호**(또는 토큰)만 넣고 '로그인 확인'을 누른다. 그 뒤 `api_get` 이 알아서 로그인
  (form-urlencoded `grant_type=password`)해 토큰을 받고, 만료되거나 401 이면 다시 로그인한다. 토큰은 메모리에만 둔다.
- 값은 `config/secrets.yaml` 에만 저장된다 (git·오프라인 번들 제외). 모델·채팅·실행 기록에는 계정도 토큰도 나가지 않고,
  응답에 섞여 와도 `***` 로 가려진다. 채팅에 비밀번호를 쓰면 저장·전달 전에 가려지고, 에이전트가 채팅으로 비밀번호를 달라고 하면 되돌려 보낸다.
- `settings.yaml` 로 직접 쓸 때: `auth: {kind: login, login_url: …, username_secret: X_USERNAME, password_secret: X_PASSWORD}`
  또는 `auth: {header: Authorization, secret: MES_TOKEN, prefix: "Bearer "}` (값은 `config/secrets.yaml` 이나 같은 이름의 환경변수).
- API 이름은 도구에 쓰는 짧은 이름(소문자·숫자·한글·-)이고, 사용자가 준 이름·문서 제목은 함께 저장돼 화면·연결 현황에 보인다.
- 같은 서버(호스트:포트)에 저장한 계정은 다른 이름으로 다시 등록해도 찾아 쓴다. 등록을 지우면 그 등록에만 쓰인 계정·토큰도 지운다.
- 계정이 아직 없으면 먼저 인증 없이 보내 본다 (헬스체크 같은 공개 경로는 그대로 된다). 401·403 이면 그때 계정을 넣으라고 안내한다.

**서버 문서가 안 열릴 때 (저장한 문서 파일)** — 브라우저로 저장한 Swagger 화면(HTML)이나 `openapi.json` 을 작업 폴더에 두면
`fetch_url` 에 그 파일 경로를 주어 읽고(메서드·경로·요약·기능 그룹·자물쇠 표시), `add_api(url=API 주소, docs_file=파일)` 로 등록한다.
이때 서버 문서는 읽지 않고, 등록 결과에 '엔드포인트 출처: 사용자가 준 문서 파일' 을 적는다 (서버 명세로 등록하면 '출처: 서버의 API 명세').
저장 화면에는 인증 방식이 없으므로 자물쇠 표시만 알리고, 방식은 관리 화면 인증 칸에서 정한다.

**지시서 · 절차** (`agent/directives.py`) — 사용자가 "이 파일에 적힌 순서대로" 처럼 지시 파일을 주면, 그 파일을 읽는 순간 원문을
시스템 지침 끝의 '사용자가 준 지시' 에 고정한다 (최대 3천 자, 긴 실행에서 기록을 줄여도 남는다).
- 사용자 말이나 지시 원문에 '조회만'·'아무것도 바꾸지 말 것'·read-only 가 있으면 변경 도구(`api_send` 등)를 그 실행에서 빼고, 불려도 실행하지 않는다.
  '변경 요청 허용을 켜 달라' 는 답은 되돌려 보낸다.
- 사용자가 준 파일과 같은 이름의 파일을 다른 곳에 만들거나 고정한 지시 파일을 덮어쓰지 않는다 (같은 파일을 고치는 것은 된다).
- 번호 매긴 단계(3개 이상)를 순서대로 하라고 했으면, 최종 답에 단계별 결과가 없을 때 한 번 되돌려 보내고 그래도 없으면 `partial`.
  도구를 쓴 뒤 '이제 … 하겠습니다' 로 끝나는 답도 한 번 되돌려 보내고, 그래도 그러면 `partial`.
  단계가 '세 줄로 요약' 처럼 요약 줄 수를 정했는데 답에 '요약 제공' 이라고만 쓰면 한 번 되돌려 보내고, 그래도 없으면 `partial`.

**긴 응답 · 집계** — `api_get` 은 긴 응답을 `offset` 으로 이어 읽는다 (잘린 결과가 모델이 열 수 없는 파일을 가리키지 않는다).
응답 JSON 의 객체 목록에서 종류·상태처럼 되풀이되는 필드는 도구가 미리 세어 결과 맨 앞에 '자동 집계' 로 붙이고, 같은 엔드포인트를
다른 대상으로 여러 번 받으면 '누계' 도 붙인다 (모델이 머리로 세지 않게). 특정 필드는 `count_by` 로 센다. 띄어쓰기 없는 긴 문자열
(RLE·base64 등)은 줄여서 보여 준다. 문서로 등록한 API 에 문서에 없는 경로를 부르면 서버에 보내지 않고 비슷한 경로를 알려 준다.
수집한 사내 사이트가 없으면 사이트 검색·재수집 도구는 모델에게 보이지 않는다.
같은 목록을 페이지마다 받으면 문서의 집계 엔드포인트(stats·count·summary) 후보를 바로 알려 준다. `find_endpoint` 는 드문 낱말에
무게를 두고 낱말마다 상위 결과를 남겨, 여러 낱말을 섞은 질의에서도 관련 엔드포인트가 빠지지 않는다.
`docs` 를 구체적으로 쓸수록 모델이 경로를 정확히 고른다. 등록한 호스트는 내부망 차단에서 자동 허용된다.

**받은 결과만 근거로** (`agent/grounding.py`) — 사내 API 를 쓴 실행에서:
- HTTP 4xx·5xx 응답과 '빈 결과'(식별 필드 `…_id` 가 null 이고 나머지가 비었거나 요청 값을 되돌려 준 것뿐인 200 응답)는
  출력은 그대로 보여 주되 실행 기록에 **실패**로 남기고, "이 응답은 데이터가 아닙니다 · 실패로 보고" 를 붙인다.
  403 이면 문서에서 같은 그룹의 다른 조회 경로(권한이 다른 '내 것' 경로 등)를 함께 알려 준다.
- 이번 실행에서 본 적 없는 식별자(UUID·숫자 섞인 파일 이름·긴 코드)를 경로나 쿼리에 넣으면 보내지 않는다
  (사용자 말·지시 원문·성공한 도구 결과·API 응답 전체에 있는 값만 쓸 수 있다. 이번에 쓴 파일을 다시 읽은 것은 치지 않는다).
  잘려서 다 보지 못한 응답이 있으면 `offset` 으로 이어 읽으라고 알려 준다. 긴 목록 응답은 맨 앞에 '목록 색인'(항목 이름을 응답 순서대로)을 붙인다.
- 문서(명세)에 쿼리 파라미터 목록이 있으면 그 밖의 이름은 보내지 않고 문서의 파라미터를 알려 준다. 등록한 문서에 파라미터 정보가
  하나도 없으면(저장한 Swagger 화면 등) API 서버가 내주는 명세(openapi.json 등)를 실행마다 한 번 보고(10분 재사용) 그 파라미터를
  붙여 같은 점검을 한다 — 이때 결과에 '파라미터 출처: API 서버의 명세' 를 밝힌다. 명세도 없으면 응답을 보고 알린다:
  `limit=10` 을 보냈는데 더 많이 왔거나, `필드=값` 으로 걸렀는데 다른 값이 섞여 오면 '무시된 것 같다'.
- 긴 목록의 '목록 색인' 에는 항목마다 나누는 값(상태 등, 서로 다른 값 2~8가지)을 붙인다 — '조건에 맞는 처음 N개' 를 순서대로 고르게.
  같은 응답을 세 번째 이어 읽으면 '찾는 이름이면 바로 조회하라' 고 알려 준다.
- 빈 목록이면 '없다' 고 단정하기 전에 같은 대상을 집계 경로로 확인하라고 후보를 알려 준다 (같은 경로에 한 번).
- 컨텍스트를 줄일 때 지우거나 줄인 도구 결과는 한 줄 요약(경로 → 상태: [집계] 종류별 개수 | 이름·수 …)으로 남긴다
  (앞서 받은 값을 지어내지 않게). 긴 목록은 앞쪽 항목 이름을 응답 순서대로 남긴다. 같은 엔드포인트를 여러 대상으로 받은 '누계' 는
  "이 응답 하나의 값이 아님" 을 밝혀 응답 뒤에 붙인다 (한 대상의 값으로 옮겨 쓰지 않게).
- 최종 답과 이번에 저장한 보고 파일(.md·.txt·.csv 등)을 실행 기록과 대조한다: 근거로 적은 경로가 이번에 보낸 적 없는 것
  (값이 든 경로이거나 문서에 없는 경로)이거나, 받은 결과 어디에도 없는 식별자를 적으면 **실제로 받은 결과 요약과 함께**
  되돌려 보내고(최대 2번), 그래도 남으면 `partial` 로 기록하고 답 끝에 적는다. 한 대상(조회 경로의 마지막 식별자)을 적은 줄의
  숫자는 그 대상의 조회 결과(누계 제외, 이어 읽은 쪽 포함)에 있어야 하고, 조회가 실패한 대상의 줄은 값이 아니라 실패로 써야 한다
  ('없음 (HTTP 404)' 처럼 실패를 쓴 줄은 맞다). 보냈다가 시간 초과된 호출도 '부른 경로' 로 친다.
- 사내 API·웹 호출이 모두 실패해 응답을 하나도 못 받았으면(시간 초과·차단뿐) `done` 이 아니라 `partial`.
- 도구를 한 번도 쓰지 않고 '할 수 없다 · 알려 주시면' 으로 답하면 한 번 되돌려 먼저 시도하게 한다 (사용자에게 내부 ID 를 묻지 않는다).
- 같은 응답을 `offset` 으로 이어 읽은 호출은 '앞 호출 응답의 일부' 로 요약한다 (이어 읽기의 빈 끝을 그 경로의 실패로 보지 않게).
  성공(2xx)만 받은 경로를 답에 '실패'로 쓰면 되돌려 보낸다.
- 한 결과의 이름 목록(12개 이하)은 요약에서 자르지 않는다. 답에 적은 이름 목록이 어떤 결과의 이름과 하나만 다르게 바뀌어 있으면
  (결과에 없는 이름이 들어가고 결과의 이름 하나가 빠짐) 그 결과의 실제 이름과 함께 되돌려 보낸다.
- `count_by` 로 센 필드가 그 응답에서 모두 비어 있거나 없으면 "이 필드로는 셀 수 없음 · 항목마다 세라는 것은 항목의 상세 결과로"
  와 항목별 조회 경로 후보를 붙인다 (빈 값 하나로 'N개 모두 0' 이라고 쓰지 않게).

**사내 API 이미지 보기** (`agent/image_store.py`, `agent/imaging.py`) — 사용자가 "보여줘" 라고 하면 모델이 문서에서 이미지를
돌려주는 GET 경로(image·thumbnail·preview·original 등)를 `api_get` 으로 부른다. 이미지 응답이면
- 관리 서버가 받은 바이트를 그 실행의 폴더(`data/runs/<실행>/images/`)에 저장하고 작은 PNG 썸네일(긴 변 320)을 만든다
  (BMP 는 외부 라이브러리 없이 줄인다. Pillow 가 깔려 있으면 다른 형식도). 모델에게는 "이미지 #n 'name' 을 붙였음" 한 줄만 간다
  — 이미지 바이트는 모델 입력·채팅·실행 기록에 들어가지 않는다. 이미지가 아닌 이진 응답도 글로 풀지 않는다.
- 채팅 답변 아래에 썸네일 격자(번호 · 파일명 · 크기)가 보이고, 누르면 크게(긴 변 1600 PNG, 작은 원본은 그대로) 본다.
  한 번에 12장씩 그리고 '더 보기', 한 실행에 최대 48장.
- 받지 못한 장(404 · 권한 없음 · 대상이 없다는 빈 응답 · 이번 실행 결과에 없는 지어낸 이름)은 그 자리에 빨간 점선 칸으로
  '이미지를 찾을 수 없음' 과 이유를 그린다 (이미지 자체를 돌려준다고 문서에 적힌 경로일 때).
- 화면은 `/api/v1/runs/<실행>/images/<번호>/<thumb|view|original>` 로 받아 둔 파일만 받는다 — 주소에 인증 정보가 없고, 브라우저는
  사내 API 에 직접 가지 않는다. 대화를 다시 열면 저장된 이벤트로 다시 그리고, 대화를 지우면 이미지도 지운다. 인터넷(CDN) 없이 동작한다.
- **원본 보관 기간**: 받은 원본(`*.orig.*`)과 크게 보기용(`*.view.png`)은 `images.keep_days`(기본 7일, 설정 · 프롬프트 › 설정 '이미지 보관')가
  지나면 지운다. 썸네일은 남아서 지난 대화도 격자는 보이고, 원본을 열면 "보관 기간이 지나 지웠습니다 — 썸네일만 남아 있습니다" 가 나온다.
  정리는 관리 서버를 켤 때와 새 실행을 시작할 때 한다.
- 이미지를 보여 달라는 요청이면(‘이미지·사진 … 보여줘’, 파일 이름 + 보여줘) 시스템 지침의 사내 API 칸에 문서에서 뽑은 '이미지 자체를
  돌려주는 조회 경로' 를 붙인다 (이름으로 받는 경로 · 미리보기/썸네일 먼저). 이미지를 한 번도 받지 않고 끝내려 하면 한 번 되돌려 보내고,
  끝내 한 장도 표시되지 않으면 `partial`.
- 이미지 라벨: ID 로 부른 경로라도 앞서 받은 결과에서 그 ID 의 이름(파일명 등)을 알면 그 이름을 쓴다. 같은 이미지를 여러 경로로
  시도해 한 번이라도 표시됐으면 화면에서 그 이름의 실패 칸은 빼고, 실패만 있으면 마지막 것만 보인다.
- 여러 장을 한 번에 붙이는 `show_images` 도구도 있다 (기본 intranet 용도에는 도구 수 한도 때문에 넣지 않았다 — 필요하면 용도에 추가).

## 공유 경로 · 파일 탐색기 (`general` 프로필)

채팅에 `\\서버\공유\폴더\파일.xlsx`, `Z:\프로젝트\사양서`(네트워크 드라이브), `file://서버/공유/…` 를 붙이면 그대로 읽는다
(`agent/locations.py`, `agent/documents.py`).
- **처음 보는 위치는 묻는다**: 허용 목록(`config/shares.yaml`)에 없는 위치를 읽으려 하면 '모두 승인' 중에도 "이 폴더와 그 아래 · 읽기 전용,
  허용할까요?" 를 묻는다. 허용하면 목록에 남아 다음부터 묻지 않고, 거부하면 읽지 않는다. 사내 http(s) 공유 링크도 처음 보는 주소면 같은 식으로 묻는다.
- **읽기 전용**: 공유 위치에는 쓰지 않는다 (결과는 작업 폴더에 저장). 공유를 읽은 실행은 그 뒤로 자동 승인을 끈다 (파일 안의 지시문 방어).
- **열 수 없는 곳**: 에이전트 폴더(작업 폴더 제외) · 설정 · 비밀 저장소 · 실행 기록(data) · 모델 파일, Windows · Program Files · ProgramData ·
  사용자 AppData, 드라이브 루트는 허용 목록에 넣을 수도, 채팅·화면으로 열 수도 없다. 이 PC 자신의 공유(`\\localhost\C$\…`, `\\127.0.0.1\…`,
  `ADMIN$`)는 실제 로컬 경로로 바꿔 같은 검사를 한다. `\\?\` 같은 장치 경로는 거절.
- **경로는 에이전트가 도는 이 PC 기준**: 다른 PC 의 `C:\Users\…\Desktop` 은 여기 없으므로 '경로 없음 — 작업 폴더에 올려 주세요' 로 안내한다.
  실패는 `연결 안 됨`(서버 꺼짐 · 이름 없음 · 8초 시간 초과) / `별도 계정 필요` / `경로 없음` / `권한 없음` 으로 나눠 알린다.
  작업에 적은 위치를 도구로 열어 보지 않고 '못 연다 · 없다' 고 답하면 한 번 되돌려 직접 시도하게 한다.
- **형식**: 엑셀(xlsx, 표준 라이브러리로) · PDF · 워드(docx) · CSV · 텍스트, 이미지는 크기 정보만 (모델에게 바이트를 보내지 않는다).
  문서는 50MB · 시트당 5천 행까지, 큰 폴더는 개수 · 합계 크기 · 최근 수정 파일 + 앞쪽 200개만, 검색은 파일 수 · 시간 한도에서 멈추고 그렇다고 알린다.
- **공유 계정**: 별도 계정이 필요한 공유는 '상태 · 연결' › **공유 위치** 에서 아이디 · 비밀번호를 넣는다. 비밀 저장소(`secrets.yaml`)에만
  저장되고 화면 · 채팅 · 모델 입력 · 실행 기록 · 주소에 나오지 않는다 (`WNetAddConnection2` 로 연결만 한다).
- **파일 탐색기** (사이드바): 작업 폴더와 허용한 공유 위치를 연다 — 경로 표시줄 · 위로 · 이름/크기/수정일/종류 정렬 · 이름 거르기 · 더 보기(200개씩),
  파일을 누르면 미리보기(이미지 · 표 · 문서 글 · 텍스트 · 마크다운, 그 밖은 '미리보기 불가'). **이 파일로 작업 시키기** / **이 폴더로 작업 시키기** 는
  경로를 채운 채 채팅으로 간다. 화면의 미리보기도 같은 허용 목록 · 보호 구역 검사를 탄다 (API `/api/v1/locations`).

## 하네스 (마크다운으로 관리하는 지침 · 역할 · 자료)

관리 화면 **설정 · 프롬프트 › 하네스** (관리자만). Claude Code 의 마크다운 하네스와 같은 모양(위쪽 `---` 머리말 + 본문)이지만 특정 공급사 이름을
쓰지 않는다 — 모델이 로컬이든 OpenAI · Claude · Gemini 든 같은 파일이 적용된다 (`agent/harness.py`, 파일은 `harness/`).

```
harness/
  AGENT.md                    공통 지침 — 모든 실행의 시스템 지침에 붙는다
  agents/<역할>.md             역할 = 입력창의 용도 (머리말: name · description · tools / 본문 = 역할 지침)
  commands/<이름>.md           입력창 '/이름' 명령 (머리말: description · argument-hint / 본문 = 보낼 요청, $ARGUMENTS = 뒤에 친 글)
  <폴더>/…/*.md                자료 — 사용설명서 · 에러 대처 · 점검 절차 같은 QA 자료 (머리말: title · description · tags)
  <폴더>/AGENT.md              (선택) 그 폴더 자료에 대한 지침 + 대상 회사 (companies: [A사]) — 비우면 모든 회사, 아래 폴더도 따른다
```
- **자료는 통째로 넣지 않는다**: 시스템 지침에는 자료 목록(경로 · 제목 · 설명)만 붙고, 에이전트가 `search_knowledge`(낱말 · 에러 코드로 찾기)와
  `read_knowledge`(나눠 읽기)로 필요한 부분만 꺼내 읽는다 (16k 로컬 모델도 넘치지 않게). 자료가 있으면 어느 용도든 두 도구가 자동으로 붙는다.
- **대상 회사**: 폴더마다 '대상' 버튼으로 회사를 고르면 그 회사 사람의 실행에만 그 폴더 지침 · 자료가 쓰인다 (로그인 사용 모드).
  관리자와 혼자 쓰기는 전부 쓴다. 회사가 없는 사용자는 대상이 빈 폴더만.
- **역할 파일**: `tools` 는 이 에이전트의 도구 이름 또는 Claude Code 식 이름(`Read, Grep, Bash` → read_file · search_files · run_command).
  `model` 칸은 쓰지 않는다 (모델은 입력창에서 고른다). 같은 이름의 기존 용도(`config/agents/*.yaml`)보다 우선한다 — '기존 용도를 역할 파일로 옮기기'로
  한 번에 옮길 수 있다.
- **파일 올리기**: md · txt 는 그대로, PDF · 워드 · 엑셀 · CSV 는 글로 바꿔 마크다운 자료로 넣는다.
- **작업 폴더의 지침 파일**: 실행하는 작업 폴더(와 그 위 — 사용자 작업 폴더까지)에 `AGENT.md` · `AGENTS.md` · `CLAUDE.md` · `GEMINI.md` 가 있으면
  지침으로 붙는다 (가까운 폴더 것이 나중에).
- **하네스 여러 개 (회사 · 프로젝트)**: 설정 › 하네스 줄의 `＋ 새 하네스` 로 회사(🏢)·프로젝트(📂) 단위 하네스를 만든다 — `harnesses/<이름>/` 에
  위와 같은 모양(지침 `AGENT.md` · 용도 `agents/*.md` · 자료 폴더)으로 저장되고, 하네스 안의 `＋ 새 용도` 로 그 하네스 전용 용도를 만든다.
  실행에는 **공통 + 그 사람 회사가 대상인 회사 하네스(저절로) + 입력창에서 고른 하네스**가 합쳐져 붙는다. 입력창 순서:
  모델 · 추론 · **하네스** · 용도 · 위치 · 승인 — 하네스를 고르면 그 하네스의 용도가 용도 목록에 더해진다 (이름이 같으면 고른 하네스 것).
  다른 하네스 자료의 경로는 `@<이름>/폴더/파일.md`. 워크플로 노드도 **하네스 + 용도**를 고른다 (비우면 입력창에서 고른 하네스).
  로컬 · API · CLI 모두 같은 하네스가 붙는다.
- **입력창 '/' 명령** (`web/src/features/chat/slash.ts` · `SlashMenu.tsx`): 입력창 맨 앞에 `/` 를 치면 목록이 뜬다 (↑↓ · Enter 실행 · Tab 이름 채우기 · Esc).
  ① 화면 명령 — `/new` `/model` `/effort` `/harness` `/role` `/workflow` `/approve` `/steps` (선택 칸을 바꿈), 로컬·API 대화는 `/usage` `/context` `/retry` `/stop`,
  CLI 대화는 `/mode` `/rename` `/instructions` `/attach` ② 하네스 명령 — 붙는 하네스(공통 + 회사 + 고른 것)의 `commands/*.md` 를 펼쳐 요청으로 보냄 (어느 모델이든)
  ③ 기본 요청 `/init` (폴더 지침 파일 만들기) · `/review` (검토) — 로컬·API · Codex ④ CLI 명령 — Claude Code(SDK `get_server_info`) · Gemini(ACP
  `available_commands_update`)가 알려 준 것, 그대로 CLI 로 보냄 (`GET /api/v1/claude-code/commands` — 엔진별 마지막 목록을 남겨 새 대화에도). 이름이 겹치면 ①→②→③→④.

## 외부 AI 모델 · 로그인 사용 (고객사가 이 서버에 접속)

두 가지를 각각 켜고 끈다. 새로 설치하면 **로그인 먼저 + 로컬 모델**이다 — 처음 들어오면 '첫 관리자 만들기'(서버 PC 에서만),
그 뒤로는 누구든 로그인 화면부터. 로그인 없이 쓰는 '혼자 쓰기'는 관리자가 접속 설정에서 일부러 켤 때만.

**외부 AI 모델** (`agent/providers.py`, Claude 는 `agent/llm_anthropic.py`) — 관리 화면 **관리 › 외부 AI 모델**
- 회사(우리 쪽)가 공급사 콘솔에서 발급받은 **API 키**를 넣으면 바로 연결을 확인하고 쓸 수 있는 모델 목록을 받는다
  (OpenAI · Claude(Anthropic) · Gemini(Google), 연결 개수 제한 없음 · 같은 공급사 여러 개도 가능). 처음엔 최신 3개만 켜진다.
- **Claude 는 회사 계정 로그인도 된다** (연결 방식 '회사 계정 로그인' → '추가하고 로그인', 이후 카드의 'Claude 계정으로 로그인'):
  서버가 Anthropic 공식 로그인 도구(`runtime\ant\ant.exe auth login --profile <이름>`)를 대신 띄운다. **서버 PC 에서 누르면** 그 PC 에
  브라우저가 열리고, **다른 PC 에서 누르면** 화면에 로그인 주소가 나오고 받은 코드를 화면에 붙여 넣는다. 회사 Claude Console 계정으로 로그인 ·
  조직/워크스페이스를 고르면 끝나고, 모델 목록을 저절로 받는다. 토큰은 `%APPDATA%\Anthropic` 에 공식 도구·SDK 가 저장하고 갱신한다
  (이 프로그램은 비밀번호·토큰을 보지 않는다, 요금은 그 조직). 만료되면 같은 버튼으로 다시 로그인. `ant.exe` 는
  github.com/anthropics/anthropic-cli 의 Windows 배포본(v2.9.0, 체크섬 확인)이다.
- 입력창의 모델 선택에 **로컬 (이 서버)** 와 **외부 모델** 이 늘 함께 보인다 (아직 연결 전이면 '관리자가 연결해야 함',
  관리자에게는 '외부 모델 연결하기…' 바로 가기).
- 입력창에서 **추론 강도**를 작업마다 고른다. 외부 모델: 기본 · 낮음 · 보통 · 높음 (Claude 는 아주 높음 · 최대까지), '기본'은 관리자가
  연결에 정한 값, OpenAI · Gemini 는 '높음'보다 위를 고르면 '높음'으로 보낸다. 로컬 모델: 낮음 = 생각을 끄고 빠르게, 높음 = 생각을 켜고 꼼꼼히,
  기본 = 용도 설정대로.
- 입력창의 모델 선택에 로컬 모델과 **☁ 외부 모델**이 함께 보인다. 고른 모델은 브라우저에 기억되고 실행마다 그 연결로 돈다
  (외부 모델 실행은 로컬 모델 차례를 기다리지 않는다). 키는 `config/secrets.yaml`(PROVIDER_<ID>_KEY)에만, 화면엔 끝 4자리만.
- 모델별 컨텍스트 길이(기본 128k, Claude 는 공급사가 알려 준 값)를 관리 화면에서 바꾼다 — 16k 로컬 기준의 줄이기 장치는 이 값으로 동작한다.
- Claude: 공식 `anthropic` SDK. 적응형 추론 블록을 받은 그대로 다시 보내고(대화를 줄여 맞지 않게 된 블록은 `drop_block` 으로 버림),
  자동 프롬프트 캐시, 지원 모델의 거절 대비 서버 쪽 대체 모델(`fallbacks: "default"`)을 켠다. OpenAI·Gemini 는 OpenAI 호환 주소로 부르고
  로컬 전용 값(enable_thinking · top_k · temperature 등)은 보내지 않는다. Gemini 3 의 사고 서명(thought signature)은 다음 요청에 그대로 돌려준다.
- 공급사 오류는 키 틀림 · 권한 · 한도/요금 초과 · 모델 접근 불가 · 공급사 장애 · 인터넷 안 됨 · 시간 초과로 나눠 알린다.
- **OpenAI · Gemini 의 계정 로그인은 막혀 있다**: OpenAI 의 'Sign in with ChatGPT' 요금제 사용은 오픈소스 앱·승인받은 앱만 되고
  (상용·원격 서버 앱은 OpenAI 에 신청 필요), Google 은 Gemini 앱·CLI 로그인을 다른 프로그램에서 쓰는 것을 약관으로 금지한다.
  Claude 도 claude.ai 의 Pro·Max **구독** 로그인은 다른 프로그램에서 못 쓴다 (위의 Console 계정 로그인과 다르다). 화면에 이유가 보인다.
  (아래 **CLI** 는 다르다 — 이 프로그램이 계정 토큰을 쓰는 것이 아니라, 공식 CLI 가 스스로 로그인하고 부르는 것을 그 CLI 의 연동 방식
  (Claude Agent SDK · Codex app-server · Gemini ACP)으로 화면에 중계한다. 그래도 개인 구독을 회사·고객 업무에 쓰는 것은 각 공급사 약관을 확인한다.)
- **폐쇄망 스위치**(관리 › 접속 설정): 켜면 외부 연결을 하나도 시도하지 않고 입력창에서도 사라진다.

**로그인 사용** (`agent/accounts.py`, 계정 DB `data/accounts.db`, 설정 `config/access.yaml`) — 관리 화면 **관리 › 접속 설정**
- **기본은 로그인 먼저**: 관리자가 없으면 로그인 화면 대신 '첫 관리자 만들기'가 뜬다 — 다른 PC 에서 먼저 들어온 사람이 가로채지 못하게
  **서버 PC(127.0.0.1)에서만** 만들 수 있다 (지금까지의 기록은 그 관리자 것이 된다). 그 뒤로는 누구든 로그인 화면부터 본다.
- 혼자 쓰기(로그인 없음)는 관리 › 접속 설정의 '로그인 끄기'로만 (켜져 있으면 사이드바 아래에 '혼자 쓰기 · 로그인 없음 / 로그인 사용 켜기').
- 서비스 이름(기본 'AI Agent')은 관리 › 접속 설정에서 바꾼다 (로그인 화면 · 사이드바 · 브라우저 탭).
- **관리 › 사용자 · 회사**: 회사(허용 계정 수 · 쓸 수 있는 용도)를 만들고 계정을 발급한다 → 임시 비밀번호가 한 번 보인다 → 받은 사람은
  첫 로그인 때 새 비밀번호를 정한다. 비밀번호 재설정 · 사용 중지 · 역할(관리자/사용자).
- **30일 비밀번호 변경**: 마지막으로 바꾼 지 30일(설정값)이 지나면 로그인할 때 바꾸라고 안내한다('나중에' 가능).
- **비밀번호 찾기**: 로그인 화면 '비밀번호를 잊었어요' → 관리자 화면에 요청이 뜬다 → 관리자가 임시 비밀번호를 만들어 직접 전한다 (메일 없음).
- **나누는 것**: 대화·실행 기록·작업 폴더(`workspace/users/<아이디>/`)·받은 이미지·공유 위치 허용은 각자 자기 것만. 관리자는 **관리 › 기록 · 사용량**에서
  전부(사람·회사·모델별 실행과 토큰)를 보고 대화를 열 수 있다. 승인·중지는 실행한 사람만.
- **관리자만**: 상태·연결, 설정·프롬프트, 관리, 로컬 모델 바꾸기·모델 서버 켜기/끄기, 채팅 도구 중 사이트·API 등록·주소 허용.
- **사내 API 본인 계정**: 로그인으로 받는 사내 API 는 각자 **내 계정 › 내 사내 API 계정**에 넣은 자기 계정으로 조회한다
  (`config/user_secrets.yaml`). 없으면 다른 사람·공용 계정으로 대신 조회하지 않고 넣으라고 안내한다.
- **로컬 모델 차례**: GPU 가 하나라 로컬 모델 실행은 온 순서대로 하나씩 돈다 ("앞에 N개" 표시). 한 사람은 한 번에 하나씩.
- **접속 주소**: 다른 PC 가 들어올 주소(IP·도메인)를 관리 › 접속 설정에 넣는다 (여기 없는 Host 는 막는다. 이 PC 는 늘 됨).
  인터넷으로 열 때는 HTTPS(리버스 프록시 등)를 앞에 두는 것을 권한다 — 이 서버 자체는 HTTP 다.
- **관리자 비밀번호를 잊었을 때** (서버 PC 에서): `.venv\Scripts\python -m server --reset-password <아이디>` → 임시 비밀번호 출력.
  로그인 자체를 끄려면 `--login off` (또는 `config/access.yaml` 의 `login_enabled: false`).
- `config/access.yaml` · `config/user_secrets.yaml` 은 git · 오프라인 번들에 들어가지 않는다 (반입한 PC 는 혼자 쓰기로 시작).

### CLI · Claude Code · Codex · Gemini (외부 · 온라인, 관리자만)

이 서버 PC 에 설치·로그인된 **Claude Code · OpenAI Codex · Google Gemini CLI** 를 같은 대화 화면에서 쓴다 — 입력창 모델 선택의 `CLI` 묶음
(`⌘ Claude Code · 기본/Opus/Sonnet/Haiku`, `⌘ Codex · <모델>`, `⌘ Gemini · <모델>`). 대화·도구 실행은 그 CLI 가 하고, 이 서버는 중계와 승인 창을 맡는다.

- **Codex · Gemini**: 관리 › 외부 AI 모델 › CLI 탭의 Codex · Gemini 칸에서 **설치**(이 PC 에 한 번 — `runtime\<엔진>-cli` 에 npm, 전역 설정은 그대로.
  Codex 는 데스크톱 앱이 깐 `codex.exe` 도 찾는다)와 **로그인**(누르면 로그인 주소가 새 창으로 열린다 — 이 서버 PC 의 브라우저에서 한 번,
  Codex 는 ChatGPT 계정, Gemini 는 Google 계정. 로그인은 `~\.codex` · `~\.gemini` 에 남아 계속 쓴다).
  Claude Code 와 같은 지침(설정 · 프롬프트 + 하네스)을 붙인다 — Codex 는 개발자 지침(developerInstructions)으로, Gemini 는 대화 첫 요청 앞에.
  승인: 명령 실행 · 파일 수정마다 같은 승인 패널 (Codex 는 `untrusted` 정책 — Windows 에서는 Codex 샌드박스가 강제되지 않아 승인 창이 안전장치다).
  승인 방식 '편집 자동' = 파일 수정만 자동 허용, '계획' = Codex 는 실행·수정을 거절하고 읽기만, Gemini 는 계획 모드. Gemini 는 추론 강도를 받지 않는다.
  화면 기록은 이 서버 DB(`engine_messages`)에 남고, 그 CLI 의 기록은 재개(같은 대화 이어 하기)에만 쓴다. 코드 `agent/claude_code/engines.py`.

- **연결**: 관리 › 외부 AI 모델 › **CLI · Claude Code (이 PC)** 탭. 따로 연결할 것은 없다 — `claude.exe` 를 자동으로 찾는다
  (PATH → `~\.local\bin` → VS Code/Cursor 확장 → SDK 내장 순, 경로 직접 지정 가능). 로그인이 안 됐으면 이 PC 터미널에서 `claude` 를 한 번 실행.
  같은 탭에서 기본 모델·승인 방식, 작업 폴더 목록, CLI 프로세스(이전 서버가 남긴 프로세스 종료)를 관리한다.
- **쓰기**: 모델에서 CLI 를 고르고 그냥 보내면 된다. 에이전트의 새 작업과 같은 규칙으로 작업 폴더(`날짜_시각_요청 첫 문장`)를
  자동으로 만들고 그 안에서 Claude Code 세션을 시작한다 — 주소는 `/cc/<세션>`. 승인 방식(매번 묻기 · 편집 자동 · 계획 모드)은 입력창에서.
- **작업 위치** (로컬 에이전트·CLI 공통, 관리자 · 새 대화): 입력창의 `📁 기본 위치` 를 바꾸면 새 작업 폴더를 그 아래에 만든다.
  위치는 **기준 폴더 아래 상대 경로**로만 고른다 (예: `앱/로그인`, 없으면 만든다 — 절대 경로·`..` 는 받지 않음).
  기준 폴더 = 환경변수 **`AGENT_WORK_ROOT`** (절대 경로 또는 이 폴더 기준 상대 경로 · 시스템 폴더 등은 거부),
  없으면 서버 아래 `workspace` (로그인 모드면 그 사람의 폴더). 환경변수를 바꾸면 관리 서버를 다시 켠다.
  로컬 에이전트는 그 실행 동안만 고른 위치에 쓰기를 허용하고, 이어서 하는 요청은 같은 폴더를 쓴다. 일반 사용자는 고를 수 없다.
  스트리밍, 도구 카드, 승인/거부/항상 허용, 질문 답변, 파일·이미지 첨부, 중단(Esc).
  사이드바 '최근' 에 `CLI` 표시로 함께 나오고, 터미널·VS Code 에서 만든 같은 폴더의 기록도 새 대화 화면에서 눌러 이어서 할 수 있다.
- **지침 (설정 · 프롬프트 · 하네스)**: 로컬·API 모델과 같은 지침을 CLI 에도 붙인다 — 입력창에서 고른 **용도**의 역할·블록(작업 방식·개발 규격 등)과
  하네스(공통 지침 `AGENT.md` · 작업 폴더의 지침 파일 · 자료 목록)를 같은 조립 코드(`Agent.prompt_sections`)로 만들어 Claude Code 기본 지침 뒤에 덧붙이고,
  하네스 역할(`agents/*.md`)은 Claude Code 서브에이전트로 넘긴다. 로컬 에이전트 전용 조각(실행 환경 · 사내 연결 현황)만 뺀다.
  입력창의 **지침** 버튼이나 관리 › 외부 AI 모델 › CLI 에서 무엇이 붙는지 볼 수 있다. CLI 는 대화의 첫 요청 때 지침을 기록해 그 대화 동안 쓰므로,
  용도는 새 대화에서 고르고(시작한 대화는 고정), 지침을 고치면 새 대화부터 적용된다. (API 모델은 원래 로컬과 같은 루프라 같은 지침을 쓴다.)
- **추론 강도**: 입력창의 `추론:` (기본·낮음·보통·높음·아주 높음·최대) → CLI `--effort`. 대화 중에 바꾸면 다음 메시지부터.
- **원칙**: 대화 기록의 원본은 Claude Code 기록(`~\.claude\projects`) — 읽기만 하고 고치지 않는다. 권한을 건너뛰는 모드는 없다.
  화면을 닫아도 응답은 서버에서 계속되고, 다시 열면 이어서 보인다. 쉬는 CLI 는 30분 뒤 닫힌다(세션은 그대로, 보내면 재개).
- **폐쇄망**: 폐쇄망 스위치를 켜면 쓸 수 없다. 패키지 `claude-agent-sdk` 는 선택 설치(`requirements-claude-code.txt`, 약 350MB)라
  오프라인 번들에 넣지 않는다 — 없으면 CLI 탭에 '설치 필요'만 보인다.
- 코드: 서버 `agent/claude_code/` + `server/api/claude_code.py`(`/api/v1/claude-code/…`, 관리자만), 화면 `web/src/features/claudecode/`.
  데이터 `data/claude_code/` (폴더·세션 목록, 설정, 프로세스 기록 — 대화 내용 없음).

## 자주 바꾸는 설정 (`config/settings.yaml`)

- **모델 바꾸기**: 입력창 왼쪽 아래 **모델 선택**(또는 상태 탭의 '모델' 칸)에서 고르면 모델 서버가 새 모델로 다시 뜬다.
  들어 있는 모델: `qwen3-8b`(2025.4), `qwen3.5-9b`(2026.3, 기본), `qwen3.6-35b-a3b`(2026.4 MoE, RAM 64GB 활용).
  새 모델은 GGUF 를 `models/` 에 넣고 **설정 · 프롬프트 › 모델** 탭의 '모델 추가'(또는 `settings.yaml` 의 `models` 목록에 한 줄).
  같은 탭에서 모델별 컨텍스트 길이·GPU 층·추가 인자(`--n-cpu-moe` 등)를 바꾸고 '다시 켜서 적용'. 바꾼 뒤엔 `eval` 로 비교
- **MoE 모델 속도 조절**: `qwen3.6-35b-a3b` 의 `--n-cpu-moe 36` = 40층 중 36층의 전문가를 RAM 에 둔다.
  상태 탭에서 VRAM 이 남으면 숫자를 줄여(예: 32) GPU 에 더 올리면 빨라진다. VRAM 이 넘치면 늘린다
- **오프라인 번들**: 기본은 지금 쓰는 모델 + 임베딩 모델만 넣는다. 전부 넣으려면 `make_offline_bundle.ps1 -AllModels`
- **다른 폴더 접근 허용**: `allowed_dirs` 에 `{path: C:/..., mode: ro}` 추가 (쓰기는 `rw`)
- **웹 검색** (`researcher` 프로필): `web.search_provider` — `ddgs`(인터넷, 한국+미국 동시 검색) /
  `searxng`(사내 SearXNG 주소를 `web.searxng_url` 에) / `none`(폐쇄망, 검색 끔).
  사내 위키 같은 내부 사이트를 읽게 하려면 `web.allow_private_hosts` 에 호스트나 대역을 추가한다 (기본은 내부망 차단)
- **에이전트 역할(용도) 추가**: 설정 · 프롬프트 › **＋ 새 용도** (또는 `config/agents/` 에 YAML 하나, 도구는 10개 이하)

## CI/CD · 작업 방식 (TDD)

GitHub Actions (`.github/workflows/`). 모델 · llama.cpp · 진짜 CLI 없이 돈다 — `tests/conftest.py` 가 계정 · 하네스 · 모델 서버 · CLI 를 가짜로 바꿔 끼운다.

- **CI** (`ci.yml`, 모든 브랜치 push · PR): ① 서버 테스트 — Windows · Python 3.12 · `pytest` ② 화면 — `npm ci` → `npm run gen:api` 결과가
  커밋된 `src/api/schema.d.ts` 와 같은지(API 계약) → `typecheck` → `vitest` → `build`. 서버 쪽 계약(`web/openapi.json`)은 `tests/test_api_contract.py` 가 본다.
- **CD** (`release.yml`, 버전 태그): `git tag v0.1.0 && git push origin v0.1.0` → 테스트를 다시 통과하면 GitHub Release 에
  `ai-agent-<태그>.zip`(코드 + 화면 빌드) · `ai-agent-<태그>-wheels.zip`(폐쇄망 설치용 파이썬 패키지, Windows · 3.12)을 올린다.
  모델(GGUF) · llama.cpp 는 넣지 않는다 — 기존 PC 것을 쓰거나 `scripts\make_offline_bundle.ps1` 로 따로 옮긴다.
- **작업 순서**: 브랜치(`feat/…` · `fix/…`) → **테스트 먼저**(실패 확인) → 구현 → 로컬 `pytest` · `npm test` → push → Actions 초록 → PR → main.
  `main` 에 바로 올리지 않는다. API 를 바꾸면 `scripts/export_openapi.py` → web 에서 `npm run gen:api` 까지 커밋.
