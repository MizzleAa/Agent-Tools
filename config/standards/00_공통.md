# 공통 규격 (모든 언어)

## 1. 작업 순서
1. **요구 정리**: 사용자 요구를 번호 목록으로 정리한다. 뜻이 모호하면 어떻게 해석했는지 적는다.
2. **환경 확인**: 언어별 문서의 "환경 확인" 명령으로 이미 있는 도구와 라이브러리를 먼저 본다. 확인 없이 설치부터 하지 않는다.
3. **스택 선택**: 언어와 프레임워크를 고르고 이유를 한 줄로 쓴다. 이 PC에 없는 언어는 고르지 않는다.
4. **구현**: 언어별 "프로젝트 구성"대로 만든다.
5. **검증**: 아래 검증 등급의 V1~V3을 차례로 올린다.
6. **정리 후 보고**: 아래 "개발 보고 형식"을 따른다.

## 2. 프로젝트 폴더
- 작업 폴더 안에 프로젝트 폴더 **하나**(`<프로젝트명>/`)를 만들고, 산출물은 모두 그 안에 둔다.
- 탐색용·일회용 스크립트는 `<프로젝트명>/_scratch/`에 두고, 끝나면 지우거나 보고에 남긴 이유를 적는다.
- 필수 파일:
  - `README.md`: 무엇인지, 요구사항, 실행 방법, 의존성, 알려진 한계
  - 의존성 선언 파일 (언어별)
  - 자동 테스트 (언어별)

## 3. 의존성·설치
- 설치는 **프로젝트 로컬**에만 한다. 전역 설치는 하지 않는다 (언어별 방법 참조).
- **폐쇄망 전제**: 실행할 때 인터넷이 필요한 해법은 쓰지 않는다. 외부 실행 파일이나 대용량 바이너리를 내려받아야만 하는 해법은 고르기 전에 사용자에게 묻는다.
- 새로 설치한 것은 보고에 모두 적는다 (이름, 버전, 설치 위치).

## 4. 검증 등급
| 등급 | 뜻 | 예 |
|---|---|---|
| V0 | 미검증 | 코드만 작성 |
| V1 | 정적 통과 | 아래 세 가지가 모두 오류 0: ① 문법 ② 정의되지 않은 이름 ③ 모듈 로드(import). 언어별 판정 명령은 언어별 문서 |
| V2 | 자동 테스트 통과 | 단위·통합 테스트 실행 결과 |
| V3 | 핵심 시나리오 자동 실행 | 요구 기능을 **실제 입력으로 실행**하고 **관측한 값**으로 확인. 테스트는 스스로 종료해야 함 |
| V4 | 사람 확인 필요 | 화면 모양, 소리 등 자동으로 볼 수 없는 것. "확인 못 함"으로 명시 |

- **증거가 아닌 것**: 프로세스 exit code 0, import 성공(V1의 일부일 뿐 기능 증거가 아님), "창이 떴다", 타임아웃. 특히 GUI나 서버 프로그램은 끝나지 않는 게 정상이라 exit code로는 아무것도 증명되지 않는다.
- **끝나지 않는 프로그램**(GUI, 서버, 감시 루프) 테스트는 정해진 시간 안에 **스스로 종료**해야 하고, 확인한 값을 출력이나 결과 파일로 남겨야 한다.
- 로직과 UI를 나눈다. 핵심 로직은 UI 없이 V2로 테스트할 수 있어야 한다.

## 5. 완료 정의
"완료"라고 보고하려면 다음을 모두 만족해야 한다.
- 모든 요구가 **V3 이상**이거나, V4(사람 확인 필요)로 명시돼 있다.
- 빌드·테스트 명령을 보고서 그대로 따라 하면 같은 결과가 나온다.

하나라도 못 미치면 "부분 완료"로 보고하고, 무엇이 남았는지 적는다.
